# Explorer web shell

Vite + React + TypeScript app for `gantry map`. `pnpm build` writes it to `plugin/dist/explorer/` (hashed assets); the server (#33) serves that directory.

```
pnpm --filter @gantry/explorer test   # vitest + jsdom component tests
pnpm --filter @gantry/explorer e2e    # builds the UI, then Playwright: a smoke test on the mock API and
                                      # a real-server test (needs `pnpm build` at the root first)
pnpm --filter @gantry/explorer perf   # opens the synthetic 30k-function graph in Playwright and prints fps
pnpm --filter @gantry/explorer mock   # serve the built UI plus the mock API on :4173
```

Set `MOCK_PORT` if 4173 is taken. The mock's `scenario=large|hub|hub-thin` hash flag also changes `/api/meta` (repo name `acme-platform-monorepo` and counts computed from that scenario's data), so the header and status bar match the canvas. The "Debug: workspaces" tab is hidden unless the page is opened with `?debug=1` (or `localStorage.gantry.debug = "1"`); `#/debug` still works when typed. The real-server test copies `fixtures/pnpm-turbo` into a temp git repo, runs `gantry init` and `gantry map --no-open` with a temp `CLAUDE_PLUGIN_DATA`, and writes `docs/milestones/screenshots/{project-map,ego}-fixture.png`.

## Layout

Top bar (repo, short sha, view tabs, search, Cmd/Ctrl+K), left slot (filters, collapsible), center slot (canvas), right inspector (opens when `focus` is set), status bar.

## Files

- `src/api.ts`: the only module that calls the server. Types for `GraphNode`, `GraphEdge`, `Meta`, `NodeDetail`, `SearchHit`.
- `src/route.ts`: hash routes `#/<view>?focus=<id>&level=<level>&hops=<n>&sel=<id>&<filters>`. `focus`, `level` (`workspaces|dirs|files|symbols`) and `hops` (1-4) are sent to `/api/view/:id` as query params of the same name. `sel` is the node open in the inspector and never reaches the server. Every other key is a filter (`hideTests=false`, `workspaces=ws:a|ws:b`, `edgeKinds=calls|renders`); filters are sent as one `filters` param holding a JSON object, which the server's `parseOptions` reads. List values are `|` separated.
- `src/views/`: the project-map and ego filter panels (the project map's lists workspaces by short name with their counts and holds the `Show declared dependencies` toggle), the ego "pick a function" prompt, and double-click ("go into") rules in `drill.ts`. Registered from `views/index.ts`.
- `src/store.tsx`: React context + reducer. The hash is the source of truth for view, focus, depth and filters, so back/forward works.
- `src/theme.ts`: fixed kind colors (light and dark). Written as `--kind-<name>` CSS variables; canvases import `kindColor(kind, scheme)`.
- `mock/`: fixture graph and a small `node:http` server. Its responses mirror the real server's shapes (including `level`, `focus`, `hops` and filter handling for `project-map` and `ego`), so change it together with `server/api.ts` and `server/views/*`. Used by component tests and the smoke test; not shipped.

## 3D map

**Two styles, one view.** `#/map-3d` draws the **code city** by default: the 2D project map's ground plan stood up in three dimensions. `style=islands` (hash filter; the city is the default and leaves no trace in the hash; the choice is also remembered in localStorage `gantry.map3d.style`) switches to the island rendering described further down, unchanged. The panel's `City | Islands` switch sets it.

`src/canvas3d/city/` (the city is its own three.js scene; `OrbitControls` comes from `three/examples`, no new dependency):

- `model.ts` is pure and deterministic. `CityCanvas.tsx` fetches the `project-map` view for the current level and filters (Workspaces, Folders, Files; ids are the 2D map's, so `sel` and the inspector work as there), builds the 2D `Scene` (`canvas/scene.ts`) and runs the very layout the 2D map runs (`runLayout`, worker, `layoutMap`: elk boxes, nested treemap, orthogonal link routes and ports). Only one input differs: `layoutInputFor(..., stableBoxes)` sizes every workspace box as if it had contents and leaves the `src/` note out of the reserved title height, so the districts do not move by a pixel or two when the level changes (`model.test.ts` checks that they are identical at the three levels and within a few px of the 2D map's own layout). The layout viewport is the canvas size at the first layout. Ground plane: 2D x is world X, 2D y is world Z, Y is up, origin at the centre of the diagram.
- **Small workspaces.** A district with at most 3% of the biggest workspace's functions is _tiny_ (`canvas/tiny.ts`, `CityDistrict.tiny`). The city's layout input sets `tinyBoxes` (only the city does, `stableBoxes` style; the 2D map never does): a tiny workspace gets a slab of at least 140 x 76 layout units and a free 22-unit strip under it, and its rectangle in the geometry is the slab. Districts stay identical across levels. `spreadTinyEnds` (`model.ts`) re-spreads the arch ends on a tiny slab evenly along the edge they arrive on (ordered by where the other end lies so arches do not cross, in staggered lanes when more than fit one row, heads 0.7x the usual size), so the arrowheads stay at least 14px apart at the default camera. A tiny district's title is placed first, within 24px of its slab's projected quad (`rectQuadDistance`; touching under the front-left corner first, so neighbours form a column of left-aligned titles), never over another district, pill or flag; count pills keep off the arrowheads. `Focus small workspaces` in the panel (and a double click on a tiny district) frames the tiny districts and the ends of the arches that reach them (`CityView` `small`); `Reset camera` returns. `data-ends` on `[data-testid=map3d-labels]` lists arrowhead and tail positions on tiny districts (tests).
- Districts are slabs (a saturated frame under a light tint, at the workspace box). Folders are plinths: one step higher per depth, three steps at most (`depth > 3` rests on the third), on their treemap rectangle; a lone folder under a workspace and the other collapse rules are the 2D map's (`scene.skipped`, `(other)` / `(root files)` cells). Files are boxes on their treemap tile inset 7% per side (the gaps read as streets), height = functions through `makeHeightScale` (linear with a floor so a 0-function file is a flat tile and a cap so one giant file cannot dwarf the scene: cap = the largest count, but at most 2.5x the 95th percentile). At the Folders level the leaf folders are extruded (height = functions); at the Workspaces level each district carries one block (height = functions). Heights scale with the diagram's extent. Instanced meshes (slabs, plinths, buildings; about 900 boxes at the Files level) with one `MeshLambertMaterial`, ambient plus one directional light, and darker edge lines on blocks; no shadow maps.
- Arches: one tube per import link (declared-only links with `Show declared dependencies`), from the source district's port to the target's along the 2D route, in the importing workspace's colour, radius ~ sqrt(weight) (clamped), a dot at the source, a cone at the target pointing along the end of the arch, a faint ground line of the route. `archPath` lifts the route to a height that grows with its length and never below the tallest building under any sample (`HeightGrid`, margin), then smooths it (`model.test.ts` checks the clearance at all three levels). Opposite directions are separate arches.
- Labels are DOM in the `.c3-overlay` (`CityScene.placeLabels`, every camera change, in this order): district title blocks (name bold, `type · N functions · M files`; the compact `type · N fn · M files` for districts that are small on screen) on the camera side below the front-left corner, else around the district's outline, else inside its own floor, else further away with a coloured leader line and dot to the nearest point of the district, never over another district's outline, the key or another title; flags (below); count pills on every arch (at most 40 arches, else the 8 heaviest) at the first of 12 spots along the arch from about a third of the way that is free, nudged up or down when needed; folder captions (`▣ name · N fn`, the size part only when the whole text fits) at the front edge of a plinth, else the back edge, by size, only where the text fits. With a district hovered, selected or hovered in the list, only its arches are at full strength and carry `A → B: N imports` pills (the rest are dimmed to 10%).
- Largest files: the numbered flags use the ranking of the left panel (`rankedFiles`, from the same `project-map` data; the panel reads it through `mapUi.cityData`) and `placeFlags` (`labels.ts`, `decollideMarkers`: pole foot at the building's roof, a 20px disc 30px above it, discs never overlap and none is dropped). Hovering a list row highlights its flag and raises the building; clicking a row selects the file and flies the camera to it.
- Camera: perspective, FOV 30, 50 degrees above the ground seen from the front-left (22 degrees) so the 2D map's left-to-right flow reads left to right; `fit` finds the smallest distance that keeps every district floor, a strip for its title and every arch inside the free area (the key and the controls are kept clear) and centres the content in it; it is the same fit for the three levels. Panel buttons: `Top view` (straight down, the 2D map's arrangement), `Angled view` (default), `Focus small workspaces`, `Reset camera`; `Auto-rotate` stays off by default and is disabled with `prefers-reduced-motion` (no camera animation either). Orbit, zoom and pan as before; a click selects (`sel`, inspector), a double click selects and flies; a click on a district in the list selects it without flying (its arches are all over the map). `data-districts`, `data-flags` and `data-pills` on `[data-testid=map3d-labels]` are the test hooks (district floors in world and screen coordinates, flag positions, pill positions); `data-frame-ms` / `data-frames` on the canvas host report CPU time per frame (`perf/perf.spec.ts` asserts under 16 ms while orbiting the large mock at the Files level on the GPU).
- Key (bottom-left): `District = workspace (area = functions) · Block height = functions · Arch A → B = A imports from B (colour = importer, number = imports) · Flags = largest files, listed on the left · Tests hidden`.
- Tests: `city/model.test.ts` (rect to box, height scale floor/cap/monotonic, districts equal the layout's rectangles and are the same at every level, footprints inside folders and districts, arch clearance, flags de-collision, screen geometry), `canvas3d.test.tsx` (style and camera controls), `e2e/map3dCity.spec.ts` (writes `map-3d-city-{workspaces,folders,files,files-top,files-dark,selected,small-focus}.png` from the large mock). The island tests run under `style=islands`.

`src/canvas3d/` renders the `map-3d` view (layoutHint `force-3d`) with `3d-force-graph`/three.js in a lazy chunk. `layout.ts` is pure and deterministic (seeded by id hashes, fixed ticks, no `Math.random`); `scene.ts` is the three.js side; `MapPanel.tsx` is the left panel (level, hide tests, auto-rotate, reset camera, workspace legend). Hash route: `#/map-3d?level=workspaces|dirs|files&hideTests=false&sel=<id>`. `level` (default `dirs`) goes through the route's `onRouteChange`, `hideTests` (default true) through the filters, like the project map. Clicking a node or island sets `sel` (inspector); the view's `focus` is not used. Double-click flies the camera to the node; it does not call `onDrill`, because the 3D map has no subtree view (the level switch is the zoom). Island colours come from `src/workspacePalette.ts`, shared with the project-map panel. Readability on big monorepos: workspace nodes carry `shortLabel` (the npm scope shared by most workspaces is stripped, `server/views/labels.ts`; the project map sets it too, the full name stays in `label` for tooltips and the inspector). **One picture at every level:** island radius is `islandRadius(functions)` and island centres come from `placeIslands`, which only sees workspace function counts and workspace-to-workspace import weights, so Workspaces, Folders and Files show identical islands, arcs and default camera (`layout.test.ts` checks it); only what is drawn inside an island changes (one sphere per workspace; folder spheres; file spheres grouped in one faint bubble per folder, shaded per folder). Islands lie roughly in one plane (a shallow dome adds depth) and the default camera is the candidate direction in a cone around the plane normal with the least projected disc overlap (`bestViewDir`); orbiting still works. Pair gaps follow `islandGap`, generous for small islands so arrows and names fit. **Inside an island (round 3):** folders are discs packed without overlap (`packCircles`/`packFolders`, radius ~ sqrt(functions), deterministic) on a flat disc through the island centre that faces the default camera; folders without functions are not drawn (the island tooltip says "+N empty"). The Files level reuses the same folder discs (same positions) as faint rings, with the files as sunflower dots inside (`sunflower`: biggest file in the middle, dot radius ~ sqrt(functions)); no import lines are drawn by default, only those of the hovered or selected node. **Arcs:** `routeArcs` bows the two arcs of an opposite pair to opposite sides, raises an arc until it clears the islands between its ends, and spreads arc starts and arrowhead tips around an island's rim (at least 14px apart on screen). Every arc has a count pill (up to 40 arcs, else the heaviest 8) in the half nearer its source, with a small arrow glyph rotated along the arc towards the imported workspace. Labels are placed in screen space (`scene.ts`, `layoutLabels`) with arrowheads, pills, the key box and island discs as obstacles: island names sit fully outside every island disc, folder names inside their sphere when it is big enough else beside it with a leader of at most 24px, file names only for the ranked files (see below), in full or without extension, never cut in the middle. **Files level, largest files:** the ranked files (the same top 15 as the left panel's "Largest files" list, see the project map section) get a larger dot with a ring in the island colour (a sprite, not pickable), an 18px numbered marker beside the dot with a leader of at most 14px (`rankData` in `layoutLabels`: placed after island names and arc pills, before folder captions; the most crowded dots choose first; never overlapping each other, never covering another ranked dot if avoidable; a marker with no room that near goes further once the captions are placed but is always shown) and, only when there is room, the file name next to its marker or dot (at most 28px from the dot, never over another island; the name is also tried without `· N fn` and without its extension). No other file is named by default (hovering a row or a dot names that file). Folder captions are bold with a small folder glyph at the upper left of their ring; file names are regular weight. Hovering a list row enlarges the ring and the marker; clicking it selects the file and flies the camera to it. Test hooks on the label overlay: `data-ranks` (rank, id, marker centre, dot centre and radius), `data-isl`/`data-dot`/`data-dot-r` on file names. The key and the "How to read it" block say `Numbers = largest files, listed on the left`. The panel's "How to read it" block collapses to one line (open on a first visit to a map with up to 6 workspaces, remembered in localStorage).

Text is DOM, not WebGL: `scene.ts` keeps an overlay (`.m3-overlay`, with an SVG layer for leader lines) and places every label in screen space each frame, in this order (an earlier label is never covered by a later one): the hovered node; island blocks (name on the first line, a smaller caption on the second, one rounded box that is always placed as a unit; big islands carry it on top with a short tick, small islands get a callout on a ring around the cluster with a leader line, so every island is named at every level); arc labels (the long `A → B: N imports` for the hovered or selected island's arcs, else count pills on the 6 heaviest import arcs); folder labels beside their spheres (`name · N fn`, with a shared leading `src/` dropped; at least the top 6 folders on each big island) at the Folders level, and at the Files level faint folder captions (top 5 per big island), the 3 biggest file names per big island, and the rest on hover. Hovering or selecting an island (or its legend row) reveals more of its folders and files. Long names wrap onto two lines (CSS) and the full name is in the tooltip. A key (`.map3d-key`, bottom-left) says what island, arrow and thickness mean and, with Hide tests on, "Tests hidden". Arrowheads are cones of a fixed pixel size just outside the target island, in the target's colour at full opacity, and the tube stops at the base of the head. Arcs: only imports by default (`Show declared dependencies` adds `depends_on`-only links), width is sqrt(weight). The left panel puts a "How to read it" block under the level switch and the workspace list below; the function-kind legend is not shown for this view. Auto-rotate is off by default. The mock API serves a second, monorepo-shaped dataset (3 huge and 8 tiny workspaces, one with a 31-character unscoped name) for `#/map-3d?scenario=large`; the e2e writes `map-3d-large-{workspaces,folders,files}.png` from it and checks that every island is named, that no two labels overlap and that the three levels place the big islands' blocks identically.

The Playwright tests need software WebGL (`--use-angle=swiftshader`) and write `docs/milestones/screenshots/map-3d.png` (mock data) and `map-3d-fixture.png` (real server, pnpm-turbo fixture).

## Canvas slot

A view returns `layoutHint` from `/api/view/:id`. The shell renders the component registered for that hint and falls back to the default, the placeholder windowed list.

```ts
import { registerCanvas, type CanvasProps } from "./slots.ts";

// CanvasProps: { nodes, edges, layoutHint, focus, onSelect, onHover }
registerCanvas("force", ForceCanvas); // eager
registerCanvas("3d", Canvas3d); // Canvas3d lazy-loads its chunk and renders its own <Suspense>
```

Register in `src/canvases.ts` (imported by `App.tsx`). `focus` is the focused node id or `null`. Call `onSelect(id)` to focus a node (updates the hash and opens the inspector) and `onSelect(null)` to clear it. Call `onHover(id | null)` for hover state. Use `kindColor` from `theme.ts` for node colors.

## Graph canvas (`src/canvas/`)

The canvas registered for `nested-elk`, `elk-layered`, `radial`, `force`, `tree-lr`, `bowtie` (the ego view, below), `columns`, `clusters` and the server hints `layered`, `tree`, `grid`. `CanvasHost` wraps it with a List / Graph toggle and lazy-loads it. `GraphCanvas.tsx` builds the scene and picks one of two renderers: hierarchical data (the project map: workspaces, folders, files, functions) gets the treemap canvas; flat graphs (ego, debug) keep the sigma canvas.

### Project map: workspace boxes with a treemap inside

- `mapLayout.ts` (in the layout worker): workspace boxes in a layered dependency diagram (elk, orthogonal edge routing). Box area is proportional to `stats.functions` of the workspace node, with a floor (120 x 64 px) so tiny workspaces stay clickable and labelled. Units are "pixels at the fit zoom of a canvas of the given `viewport` size". The layout tries a few deterministic option sets (box shape, layering strategy, spacing 36-48 px, left-to-right or top-to-bottom, and how many layers the heaviest links may form: lighter links are routed around the placed boxes afterwards, like the declared-only ones), bisects the box area per function so the whole diagram just fits the canvas for each, and keeps the set whose biggest box ends up largest on screen (preferring one that is at least a quarter of the canvas wide). The camera fits the diagram to the canvas with 24-44 px of free space, so it fills the limiting dimension. The layout is deterministic and follows from the data, so nothing is saved through `/api/layout` for hierarchical maps (flat graphs still save). The canvas asks for a new layout when it is resized by more than 12% (the inspector opens, the window changes) and the user has not moved the camera.
- `treemap.ts`: squarified treemap (area proportional to weight, ties by id, cells laid out about 1.7x wider than tall so names fit). It is laid out in a normalized content rectangle: no header space is reserved. A file with no functions keeps a minimum weight so it shows as a thin cell. Label rules: `fitCellLabel` draws a label only when it fits at 10px or more (middle-ellipsis only in cells at least 60px wide); `fitFileLabel` tries the whole name at 11px, then 10px, then without its extension, then two lines broken at `.`/`-`/`_`/camelCase, and only then the ellipsis.
- `mapGeom.ts`: headers are a constant size on screen (workspace title block at most 44px: name up to 18px, detail line up to 12px; folder strip at most 20px (28px when a long name wraps to two lines), shown only for a folder that is at least 70 x 28px, three levels deep AND can show its whole name (wrapped to two lines, 10px at the smallest: `folderStrip` in `mapGeom.ts`, shared by `headPx` and the drawing) — a folder that cannot gets no strip and no glyph, its tiles stay and its name shows on hover; file-name strip at most 16px). The content rectangle of a container is its on-screen rectangle minus the header that fits at the current zoom; children are mapped from their normalized rectangles into it (`mapChild`), by drawing and picking alike, so picking is exact and nothing is laid out again when the zoom changes. `hierarchy.ts` `collapseChains` skips a lone folder under a workspace or folder (no box, no header; its name is added to the parent's detail line or strip, e.g. `src/`) when the container has no files of its own, or when its loose files (config files beside `src`) hold under 10% of its functions; those files then sit in one small `(root files)` group cell (`withRootFileGroups` in `scene.ts`, kind `group`, id `rootfiles:<parent id>`, hover lists the paths, clicking it means the parent). Server ids are unchanged. At the Folders level the canvas asks once for `level=files` in the background (`useMosaicFiles`, cached per focus and filters) and draws those files as a faint, unlabelled mosaic inside folders (`scene.mosaic`; not pickable).
- `mapDraw.ts` + `TreemapCanvas.tsx`: everything is drawn on one 2D canvas with its own pan/zoom camera (drag, wheel, `+`/`-`, `0` fits, Esc clears). Cells under 2px and cells outside the viewport are skipped, which keeps the 30k-function map at 60fps. Sibling cells alternate between two close tints and are separated by a contrasting 1px line. Picking descends the rectangle tree under the pointer (hover tooltip, click selects, double-click calls `onDrill`). The camera fits the whole diagram inside the free area (the strip with the controls above and the status chip below are kept clear) on load, on level change and on resize, unless the user moved it. Hovering a workspace row in the left panel outlines its box and dims the others; clicking the row's name selects it (the checkbox still toggles visibility).
- Workspace links: only import links by default; `Show declared dependencies` in the left panel adds the declared-only ones (dashed). Colour is the importing (source) workspace's: the same palette colour as its box border, darkened on the light theme and lightened on the dark one just far enough for 3:1 against the canvas (`inkAgainst` in `style.ts`); the arrowhead, the start dot and the pill border use it, and the pill number uses a 4.5:1 version of it on the solid pill background. Width is `clamp(0.8 + 0.3 * sqrt(weight), 1, 8)`; the bottom third by weight is thinner (never under 1.25px, never under 55% opacity) with a smaller (11px) pill of the same style. Up to 40 visible arrows every arrow has a count pill, above that only the 8 heaviest do (pills are de-collided along their own arrow). Hovering or selecting a workspace (or its row in the left panel) shows its links in full with `A → B: N imports` pills and dims the rest. Selecting a folder, file or function draws its links to other cells as thin curves with arrowheads (`selectionLinks` in `scene.ts`) and dims the rest.
- Names: workspace nodes carry `shortLabel` (the npm scope shared by most workspaces is stripped, `server/views/labels.ts`); the canvas, the left panel and the legend use it, the full name is in tooltips and the inspector. Counts printed on a box always come from the workspace node's own `stats`. A workspace box always shows a title: inside the box (wrapped to two lines or shrunk to 10px, detail line dropped if needed), else beside it, else on the box itself over a halo; the repo-root workspace (`ws:.`) shows `(repo root)` where the others show their type (`app`, `package`) in the detail line, and falls back to `(repo root)` as its title when its name does not fit. Link counts (pills, hover labels, arrow width) are the `imports` weight only: a `depends_on` edge never adds to them, and a pair with both keeps one arrow with the import count. The layout/timing chip at the bottom left is debug text, shown only with `?debug=1` (or `localStorage.gantry.debug = "1"`). Test hook: `data-probe` (event `gantry:probe`) lists the drawn pills, title texts and title placement.
- Routing (`mapRoute.ts`, in the layout worker): every link is its own orthogonal route on a 10px grid around the boxes (elk only places the boxes). Each link leaves and enters through its own port on a box side, ports 12px apart (boxes get enough side length for their links), starts with a filled dot on its source box and ends with an arrowhead of 11 to 15px whose tip touches the target box edge. Ports on a side are ordered by the direction their routes leave (a second pass re-sorts them from the first pass's routes), the two directions of a pair mirror each other so their lanes do not cross, and a rip-up pass reroutes links that cross others (and swaps neighbouring ports) when that removes crossings without growing the diagram. No segment enters another box and routes that share a channel in the same order at both ends do not cross inside it (unit tests check both on the large mock). Declared-only links stay near the boxes. A count pill sits on a straight stretch of its own route, preferably the first long one after the source, clear of boxes, titles, other pills, the key and (when there is room) other lines; with no such spot the search runs on along the route and relaxes the clearance before it overlaps anything.
- Key and orientation: a collapsible key at the bottom-left says what boxes, lines and numbers mean (`Line colour = importing workspace`; and `Tests hidden` / `Tiles = folders / files`). Collapsed it is one short `Key ▸`; it folds itself while the camera is zoomed past the fit so it never covers tile labels (click to reopen), and pills keep clear of it. While the camera is zoomed past the fit or the workspace title is off screen, a breadcrumb pill under the List / Graph toggle names the workspace and folders at the canvas centre (click a crumb to zoom to it) and the left panel says `Zoomed into api › routes`; folder strips stick to the top edge while their folder is partly scrolled out. The controls sit on an opaque bar.
- Labels: a folder strip is bold on a solid band with a folder glyph, wraps to two lines (up to 28px) at word breaks, shows `· N fn` whenever the name is shown and it fits, and never cuts a folder name (no ellipsis, no broken words: a strip that cannot show the whole name is not drawn at all); a file label is regular weight with no band, shown only when the whole name (or without its extension) fits on two lines, with a second `N fn` line in cells of 120 x 34px or more. A wrapper folder holding at least 90% of its container's functions is lifted and everything beside it is gathered in one `(other)` cell (`withRootFileGroups`). Boxes under 160 x 90px on screen show title and counts only until zoomed in.
- **Largest files (Files level, shared with the 3D map):** the left panel gets a "Largest files" section (`components/LargestFiles.tsx`, one component for both panels): the top 15 files by function count over the visible workspaces (`rankedFiles/rank.ts`: ties by path, tests left out with Hide tests, `Top files in` restricts it to one workspace and then lists that workspace's top 15). A row is a numbered circle ringed in the workspace colour, the full file name (wrapped, never cut), `N fn` and a muted `workspace › folder` line (short workspace name, folder without a leading `src/`). Hovering a row highlights the file on the canvas; clicking selects it (inspector) and zooms or flies to it (`rankedFiles/store.ts` carries scope, hover and focus requests between panel and canvas). The same ranking draws numbered markers on the canvas (`drawRankMarkers` in `mapDraw.ts`): 18px circles on the file's tile, dark disc and white digits (light disc on the dark theme), ring in the workspace colour, nudged apart by `rankedFiles/markers.ts` (`decollideMarkers`: never overlapping, none dropped) and kept off the key. Hovering a marker shows the tile's tooltip; test hook: `markers` in `data-probe` (rank, id, centre, radius). `MapKey` says `Numbers = largest files, listed on the left`.
- File labels at the Files level: besides the ordinary rule, the single largest file of each folder is also labelled when its whole name (or the name without extension) fits at 11, 10 or 9px on up to three lines broken at `.`, `-`, `_` and camelCase (`fitLargestFileLabel`); a name that still does not fit gets no label (no ellipsis).
- One legend: the left panel lists the workspaces with their colours (and the function kinds at the Functions level). The floating `Legend` is collapsed by default in the strip above the diagram and is not drawn at all for views that have a left panel.
- The level control decides how much data the server sends (Workspaces, Folders, Files, Functions); the map draws all of it at the fit zoom, and zooming in reveals more labels.
- `scenario=large` (mock only, like the 3D view's flag) serves `mock/largeMap.ts`: 11 workspaces (three big, eight tiny), long scoped names, nested folders, ~850 files, ~3,700 functions, weighted imports (1 to 640) and 31 declared-only links. `e2e/map2d.spec.ts` writes `docs/milestones/screenshots/map-2d-large-{workspaces,folders,files,files-dark,functions,dark,selected,zoomed,zoomed-dark}.png` from it.

### Flat graphs

- `GraphCanvas.tsx` (sigma + graphology): selection, hover tooltips, controls, keyboard. `layout.ts` (+ `layout.worker.ts`, `layoutClient.ts`): force (ForceAtlas2 from a hash-seeded start), elk layered, radial, tree, columns, clusters or grid, in a Web Worker. No `Math.random`. Positions persist through `GET/PUT /api/layout/:view` (`layouts` table): known nodes keep their saved position, Re-layout recomputes from scratch. `radial` layouts depend on `focus`, so they are not saved.
- Selection and dimming are sigma item states set in batches. Do not add a sigma `nodeReducer` or `edgeReducer`: with one, sigma re-evaluates every node and edge each time the camera starts or stops moving.
- `hierarchy.ts`: containment tree. `scene.ts`: everything derived from nodes and edges (workspace links, counts, selection sets). `zoom.ts`: the far / mid / near band reported in `data-level`. `style.ts`: workspace palette (indexed by sorted id) and theme. `synthetic.ts`: seeded 30k-function generator used by `pnpm --filter @gantry/explorer perf`.

Test hooks on the canvas element: dispatch `gantry:zoom-to` (`detail: { id }`) on `[data-testid=graph-canvas]` to fly to a node, and `gantry:probe` on `.gc-sigma` to write hit geometry (workspace boxes, links, where each title went) and a hash of the positions to `data-probe`.

### Ego view: bow-tie (`bowtie` layout hint)

The `ego` view returns layoutHint `bowtie`, drawn by `canvas/BowtieCanvas.tsx` on one 2D canvas (no WebGL, no sigma). `bowtieLayout.ts` is the pure, deterministic layout, sized for the canvas it is shown in (`layoutBowtie(nodes, edges, { w, h })`, units are screen pixels at zoom 1): the focus is a card vertically centred in the middle, callers sit in columns to its left (nearest hop next to the focus), callees to its right, hop 2+ further out on the same side. Rows are 26px tall (30px pitch). A side with more rows than fit the height is spread over up to 3 columns (column-major, nearest column first) before the rows are squeezed, and never below 18px; the camera fits the whole picture, so at fit zoom the rows stay near 26px. Rows stack: groups first (one workspace after another, largest first, "other callers" rows last), then individual nodes; hop 2+ are ordered by the average height of their neighbours. Every edge flows left to right as one curve per row, `1 + 0.8 * sqrt(weight)` wide (at most 6px), dashed when low confidence, entering the focus card at evenly spaced ports; one shared arrowhead sits at the card.

- Row budget, on the server (`server/views/egoGroups.ts`): a side at one hop has at most `maxRows` rows (option, 8-40, default 18; the explorer sends `floor((canvas height - 96) / 30)` clamped to 8-24) however the callers are spread. A side with `maxRows` nodes or fewer is shown node by node. Otherwise it starts as one row per workspace and the largest group is split into its children (workspace, folder with single-folder chains collapsed, file) while the row count stays within the budget; children of 3 members or fewer that share a parent merge into one "other callers" row, and a group with more children than the budget allows peels off its two largest and keeps the rest behind one "other callers" row, which is split again the same way. Symbols are rows only inside an expanded group. A group is one node (`kind: "group"`, `id: group:<side>:<hop>:<ws:... | dir:... | file:... | rest:<parent key> | more:<group key>:<offset>>`, `stats.members/files`, `members[]`, `workspace`) with one aggregated edge. Labels say what a row is: `ui — 201 callers in 104 files`, `ui › components/review — 9 callers in 4 files` (leading `src/` dropped, folder paths over 40 characters shortened in the middle), `review-composer.tsx — 4 callers`, `ui · 34 other callers in 21 files`. Where the canvas is too narrow for the whole label it drops the workspace, then "in N files", before it cuts anything.
- Expanding: the `expand` filter (a `|` separated list of group ids) replaces those groups by their children under the same rule, at most `pageRows` rows each (option, default 14): the largest children, then a "+N more callers in M files" group that expands to the next page. The group stays as a header node (`expanded: true`, no edges) and its rows carry `group: <id>`; expanded groups nest. An expansion that would pass the 400-node cap is skipped. Hash route: `#/ego?focus=<id>&expand=group%3Ain%3A1%3Aws%3A%40acme%2Fweb%7Cgroup%3Ain%3A1%3Adir%3Aapps%2Fweb%2Fsrc` (ids joined with `|`, URL-encoded like every filter). Clicking a group (or its caret) toggles it in `expand` together with `sel`, in one navigation; the panel's Expand all / Collapse all and the inspector's member links write the same filter. Changing the centre drops `expand`. Expanded groups are drawn as outlined blocks around their rows.
- Drawing: the focus, groups and individual rows are all labelled (rows are never thinner than 18px). Group rows are pills with a caret and a count chip on the right. Colour is by workspace, indexed by the sorted workspace ids present (`workspacePalette.workspaceColorAt`), and the left panel lists the same colours (short names, most callers first); its group list uses the same labels and wraps. The kind is in the tooltip. Column titles ("Callers · 221", "Callees · 1") are pinned to the top. Test hooks on `[data-testid=graph-canvas]`: `gantry:zoom-to` (`detail: { id }`) and `gantry:probe` (writes the drawn labels and row rectangles to `data-probe`).
- `scenario=hub` and `scenario=hub-thin` (mock only, like `scenario=large`): `mock/hubEgo.ts` serves a shared component with 221 callers and one callee, grouped by the server's row budget (`mock/egoRows.ts` is a copy of `server/views/egoGroups.ts`; `src/views/egoMock.test.ts` fails when they differ). `hub` has the callers in a few big folders (3 workspaces); `hub-thin` is shaped like a real monorepo hit: 201 callers in one workspace over 104 files in 30 folders (at most 11 per folder, most files with 1-3), 20 in another over 16 files, long scoped workspace names. `e2e/ego.spec.ts` checks the row budget, row heights and label overlap on both and writes `docs/milestones/screenshots/ego-hub-{grouped,expanded,dark}.png`, `ego-hub-thin-{grouped,expanded}.png` and `ego-small.png`.

## Filter slot

`registerFilterPanel(viewId, Panel)`, where `Panel` receives `{ viewId, nodes, edges, filters, onFiltersChange, route, onRouteChange }`. `onFiltersChange` writes the hash filters and refetches the view; `onRouteChange({ focus, level, hops })` changes the view params. Views without a panel show "This view has no filters."

`registerFocusRequired(viewId, Prompt)` marks a view that needs `focus` (the ego view): no request is sent until it is set, and `Prompt` fills the centre meanwhile. A canvas may also call the optional `onDrill(id)` prop on double-click.
