# M7 regression: V2 groundwork

Issue #264. M7 made the index repeatable and the evaluation corpus fixed before any V2 feature work: a pnpm and Node pin, a `pnpm check` that ignores local untracked files, one data directory, a store that is rebuilt when stale (schema 8), a repo name in stable IDs, byte-stable `review --json`, search that ranks the same function first with and without vectors, and a pinned public evaluation corpus. This report runs the 12 checks of the issue against `origin/main` at `7354f07` and records what each printed. Nothing is adjusted to pass: a failing check is recorded as failed with its output.

## Setup

- Machine: Apple M3 Pro Mac, 11 cores, 18 GB, macOS 27.2.1; Node v26.13.0, pnpm 10.31.0.
- Load: other agents were running on this machine throughout, so timings are inflated. Load averages (1, 5, 15 min) at the start of each timed run are given where a time is reported.
- Fixtures: each check copies the named fixture into a new git repo (`git init`, one commit), with `CLAUDE_PLUGIN_DATA` and `HOME` set to new temp directories, as the issue's Verify block says.
- Differences from the issue text, following `origin/main`: the store schema version is 8, so the stale-store check uses "schema 6, now 8" where the issue shows "now 7"; route ids are `route:repo:<workspace>:<path>` (the repo part is `repo` when there is no remote); `/api/meta` returns the counts under `counts`, not at the top level; `pnpm eval:clone` clones the 16 repos now in `evals/oss/repos.json`, not three.
