What this does and does not show:

- The three misleading cases are restructured copies of the existing function, and the set was tuned against itself. Truly different implementations of the same behaviour were found 0 of 3 times. So "3 of 3 misleading" measures renamed and restructured copies, not independent reimplementations.
- The Go embedding text renames the function's own name and its local names before embedding, so the code-vector tier compares structure and called names, not identifiers. The score above is for that text.
- This is a small seeded set (10 cases); it is a regression check, not an estimate of the rate on real code.

Run 1's backlog log: 7 rejected attempts over three rounds, then two functions left with status `failed` after 3 attempts: `internal/text/init.go#init` and `init~2`, both with `behavior not in the fact sheet: startup`. The describer wrote the word "startup" for two `init` functions and the fact-sheet check rejected it each time. Runs 2 and 3 described them. On a fixture this small a single failed function is about 5% of the described count, so the 1% bar cannot be met with any failure; the bar is the bar and the row is recorded as missed.

Two notes on what this run does not cover:

- The shared describer prompt gained a "write literals as plain words" line during M12. It was not re-measured on TypeScript, so its effect on TypeScript describer quality is unknown.
- The three runs use one model alias on one fixture; they do not measure Go descriptions of a real repository.

## Deviations from the issue text

- The #220 commit on `main` is "Every indexed file and function says which language it is in (#329)" (`57e37cf`); its subject does not start with `#220:`, so the issue's `git log --grep='^#220:'` finds nothing. The snapshot check was run with `M=57e37cf011fe129d511cbc401646504c015bdf84`. The same is true of the #224 commit (`4b0eb15`, "Search Go functions by what they do (#336)"). The follow-up `git log` over the three snapshots printed nothing, so none of #221 to #224 touched them.
- The snapshot comparison was run with the same `jq` filter and `diff` as the issue, with each `git show` written to a file first.
- README: the Status table already had an M12 row (state "In progress"); it was edited in place rather than added.

## Follow-ups

- Row 5 (missed): proposed issue below.

Title: "Go describer leaves `init` functions undescribed on the go-basic fixture (failed rate 10% in 1 of 3 runs)"

Body: In the M12 report (`docs/milestones/M12.md`), `evals/go-search/describe-run.ts --model haiku` failed 2 of 20 descriptions in run 1 (0 of 22 in runs 2 and 3), against a bar of 1%. Both failures are the two `init` functions of `internal/text/init.go`, rejected three times each with `behavior not in the fact sheet: startup`. Find out whether the fact sheet for `init` should name what runs at package load, or whether the check should accept the word. Re-measure with three runs; the bar is failed/described <= 1% in the worst run. Also decide whether the bar fits a fixture this small (one failed function is about 5% of the described count) and, if not, change the bar through the spec.
