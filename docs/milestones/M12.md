# M12 regression: Go backends

Issue #275. M12 made Go modules indexable: symbols, callers, descriptions and search by behavior, and duplicate warnings, parsed without a Go toolchain (#220 to #224). This report runs the checks of the issue against `origin/main` at `f6c21ac` and records what each printed. Nothing is adjusted to pass: a failing check is recorded as failed with its output.

What this does and does not show:

- The three misleading cases are restructured copies of the existing function, and the set was tuned against itself. Truly different implementations of the same behavior were found 0 of 3 times. So "3 of 3 misleading" measures renamed and restructured copies, not independent reimplementations.

- This is a small seeded set (10 cases); it is a regression check, not an estimate of the rate on real code.

## Re-measure after #348

Cause of the failed-rate miss: the grounding check (`identifier`) accepts a word only if it is in the shipped word list, on the hand lists, or grounded in the fact sheet. `startup` was on none of them, and the fact sheet of a Go `init` holds no such word, so a correct description ("runs at startup") was refused three times. #348 added `startup` and `startups` to the hand word list; #372 reverted that, because the fix belongs in the fact sheet and not in the validator's word lists (see "Re-measure after #372"). The table below is the measure of the word-list version.

Worst run: failed rate 0.0% (bar <= 1%: met); top-5 7 (bar >= 8: **missed**). Run 1 missed "look up a saved value by its key", "text label for the print style of a value" and "demo program entry point that prints a stored greeting". The top-5 spread across the first and second measure is 7 to 9 for the same fixture and model, so it is noise around the bar, not a regression from #348 (which does not touch search). It is recorded as missed and not adjusted.

## Re-measure after #372

#372 puts the fix for `init` where it belongs. The word list change of #348 is reverted. For a Go function named `init` the fact sheet now carries a fixed, host-written field (`runsWhen`: "Runs once at startup, when its package is loaded."), and the grounding names read its words, so a description that says the function runs at startup is grounded by the sheet. No validator rule and no word list changed. The regression test (`validate.go.test.ts`) builds the real fact sheets of both `init` functions of `fixtures/go-basic` and checks that the description is refused without the field and accepted with it. Spec section 7 describes the field; section 8 states the failed-rate rule as "0 failed on fixtures under 100 functions; at most 1% otherwise". `describe-run.ts` now prints `modelId`, the id the calls report.

`pnpm tsx evals/go-search/describe-run.ts --model haiku`, three runs, built from the #372 branch. Resolved model id of every run: `claude-haiku-5-5`.

Worst run is run 1: failed 1 (bar 0 on a fixture under 100 functions: **missed**), top-5 6 (bar 8: **missed**). Row 5 stays missed. Both `init` functions got a model description in all three runs. The bar, the queries and the labels were not changed, and no fourth run was made.

The failed function of run 1 is `internal/store/store_test.go#TestPutGet`, not an `init`: the describer wrote the search term `testputget` (the function name joined and lower-cased), which is not in the fact sheet, and it was rejected twice. The last two have the causes above.

What 10 queries and a bar of 8 can tell: two queries (`trimDashes`, `main`) missed in every run, so the best case of this fixture and model is already 8 of 10, and the bar sits on that floor. A single run cannot tell a defect from this spread, and the worst of three on this set will be at or below the bar more often than not. This report does not change the bar or the query set; if they are to change, that is a spec decision made with its reason, not one fitted to this result.

The follow-up `git log` over the three snapshots printed nothing, so none of #221 to #224 touched them.
- The snapshot comparison was run with the same `jq` filter and `diff` as the issue, with each `git show` written to a file first.
- README: the Status table already had an M12 row (state "In progress"); it was edited in place rather than added.
