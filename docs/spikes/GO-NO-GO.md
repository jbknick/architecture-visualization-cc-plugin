# M0 go/no-go report (issue #11)

Inputs: `docs/spikes/worker.md` (#2), `oxc.md` (#3), `embed.md` (#4), `describe.md` (#6). Every number below is quoted from those reports. Nothing here is rounded in a way that changes its meaning, and anything not in a report is marked as derived or unmeasured. This report is public and holds aggregate numbers only.

VERDICT: GO

Rule from the issue: GO only if descriptions are acceptable on at least one path (worker or subagent). Path A (the headless worker, verdict WORKER OK) passed the measurable description targets: 95.5% graded acceptable against a target of 85%, and 100% schema pass against a target of 98%. Path B (describer subagent) is not measured, which does not block GO because the rule needs only one path.

Operator approval: **GO, approved by Joseph on 2026-11-14** (in chat, recorded on issue #11). He also decided: the code normalizer keeps property names and well-known globals; the interactive describer-subagent run (Path B of #6) is waived and will be measured when the real describer agent exists (#27).

## Summary for the operator

The verdict is GO. The headless worker works with the spec recipe (WORKER OK), and Haiku descriptions were graded acceptable on 95.5% of 200 functions (target 85%).

Five decisions: (1) worker: WORKER OK, keep the timeboxed and strict pre-commit modes; (2) embeddings: Jina code model, 768 dimensions, initial thresholds code_vector 0.96 and semantic 0.60, to be re-fit in M2; (3) description prompt p1 is copied into the core package; (4) `renameSuggestions` stays off, since Haiku flagged none of the 23 misleading names; (5) estimates use about 950 input and 250 output tokens per function, about 0.96 s each.

Not measured: describer subagent throughput (waived by the operator; to be measured in #27), the Linux x64 sqlite-vec row, human-checked grades (a single Sonnet pass graded them), and nameFits precision.

Approving means: you accept the verdict and these values as M2 starting points, including the normalizer recommendation, and the downstream issue comments get posted. It changes no code. Thresholds and the Linux and subagent gaps remain open follow-ups.

Thresholds: code_vector 0.96 and semantic 0.60, recorded as initial values to be re-fit in M2 (#32). They come from a small hand-written set (15 + 15 pairs per task, one author, hard negatives), and the semantic value was calibrated on hand-written paraphrases, not on the LLM descriptions the product stores. Spec section 17 shows them marked "(measured in M0)".                                                                                                                                                                                                     |

Open normalizer question (from the embed spike): rename every non-keyword identifier (strict, the issue's wording) or keep property names and well-known globals. Strict normalization turns `.toUpperCase` and `.toLowerCase` into the same token, so `capitalize` and `decapitalize` normalize to identical text and score 1.000 for every model; keeping members and globals scored 0.928 for that pair on Jina and lifted Jina's best accuracy from 93.3% to 96.7%. Recommendation: rename local identifiers (parameters, `const`/`let` names, the function name) and keep property names and well-known globals. This departs from the issue wording of #23's `normalizeForEmbedding`, so it needs the operator's approval; section 17 records it as "recommended in M0, pending operator approval". The pairs the normalizer cannot fix (`min-vs-max` 0.965, `sum-vs-product` 0.926) are left to the `near` tier.
