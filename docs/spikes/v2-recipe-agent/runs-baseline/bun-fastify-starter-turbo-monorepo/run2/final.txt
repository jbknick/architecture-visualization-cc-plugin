The recipe is at `.gantry/recipe.json`, and the dry-run says `ACCEPTED`. It lists 0 routes, 2 endpoints and 2 tables.

- **Stack:** Bun and Fastify in a Turbo monorepo, with Kysely migrations for the database.
- **Routes:** 0. The repo is backend only, with no frontend pages.
- **Endpoints:** 2, which match the registrations I read in the code:
  - `GET /` (health check, in `api/index.ts`)
  - `POST /users/email` (in `api/users/create-email-user.route.ts`)
- **Tables:** 2, `users` and `user_providers`. I took the names from the `createTable` calls in `0001-init.ts`, so they use the migration's snake_case. The `Database` interface in `db/types/index.ts` calls the second one `userProviders`.

**What I couldn't express:** the generic mount and router rules didn't resolve in the dry-run, so no endpoint was composed from them. Fastify's `register(plugin, { prefix })` mounts connect plugin functions whose `fastify` parameter is the router. The engine only treats constructor expressions like `Fastify()` as routers, so every endpoint was dropped as having an undeclared receiver. I fell back to standalone endpoint rules with the `/users` prefix hard-coded for files under `api/users/`. A new resource folder with its own prefix will need another rule. Handling this generically would need plugin-function parameters to count as routers.
