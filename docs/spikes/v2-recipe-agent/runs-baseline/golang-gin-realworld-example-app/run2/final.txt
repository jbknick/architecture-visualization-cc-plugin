The recipe is at `.gantry/recipe.json`, and the dry-run says `ACCEPTED`.

- **Stack:** Go with Gin and GORM (SQLite driver).
- **Routes:** 0. This is a backend-only API.
- **Endpoints:** 20 listed. The code has 28 registrations, but the scorer normalises paths, so `""` and `"/"` collapse into one endpoint each.
- **Tables:** 7, taken from the `*Model` structs: `ArticleModel`, `ArticleUserModel`, `FavoriteModel`, `TagModel`, `CommentModel`, `UserModel` and `FollowModel`. I used the struct names because the code sets no explicit table names.

What I couldn't express: the engine wouldn't follow the router mounts into the `*Register(router *gin.RouterGroup)` functions. The mounts look like `users.UsersRegister(v1.Group("/users"))` in `hello.go`. So `mount-graph` and `param-flow` dropped all 26 endpoints registered inside those functions.

As a workaround, I wrote one rule per register function. Each rule finds the `GET`/`POST`/`PUT`/`DELETE` calls inside that function and adds a literal prefix: `/api/articles`, `/api/tags`, `/api/users`, `/api/user` or `/api/profiles`. Those prefixes are copied from `hello.go`, so the recipe needs updating if the mounts change.

`/api/ping` still comes from the normal router and group rules.
