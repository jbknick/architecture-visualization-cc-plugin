The recipe is at `.gantry/recipe.json`, and the dry-run says ACCEPTED. It lists 22 endpoints, 0 routes and 5 tables.

- **Stack:** NestJS backend with TypeORM entities. The Mongoose schemas (`@Schema`) are also in the repo. There is no frontend.
- **Endpoints:** 22. `/api/v1` is hard-coded in the rules from `setGlobalPrefix` and URI versioning v1. Each controller's path is also hard-coded, with its own rule per controller group.
- **Home controller:** it gets `GET /`, because `main.ts` excludes `/` from the global prefix.
- **Tables:** `file`, `role`, `session`, `status` and `user`, taken from `@Entity({ name })`.
- **Prefixes:** the `ancestorPrefix` rule did not work for the Nest `@Controller({ path, version })` decorator. It matched nothing even after I tried two enclosing node kinds, and I did not find out why. That is why the prefixes are literals, so a new controller needs a new rule.
- **Config value:** the real `app.apiPrefix` comes from config. I assumed it is `api` and did not confirm it.
- **Mongoose models:** I left the Mongoose schemas out. They duplicate the user, file and session tables, and their collection names would come from the class names.
- **S3 uploaders:** the local, S3 and S3-presigned upload controllers share the same paths, so `POST /api/v1/files/upload` appears once. `GET /api/v1/files/:path` comes only from the local uploader.
