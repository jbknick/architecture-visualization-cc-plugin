The recipe is at `.gantry/recipe.json`, and the dry-run says `ACCEPTED`. It lists 0 routes, 22 endpoints and 5 tables.

- **Stack:** NestJS with TypeORM relational entities. There is also a Mongoose document layer. `main.ts` sets the global prefix `api` (config default) and URI versioning.
- **Routes:** none, because this is a backend-only API.
- **Endpoints:**
  - 21 are under `/api/v1/…`: auth, auth/apple, auth/facebook, auth/google, files and users.
  - The home controller's `GET /` is excluded from the global prefix in `main.ts`.
  - The s3 and s3-presigned file controllers register the same `POST /api/v1/files/upload` as the local one, so it appears once.
- **Tables:** `file`, `role`, `session`, `status` and `user`, taken from the `@Entity({ name })` decorators. I left out the Mongoose `@Schema` classes. They describe the same data and don't give an explicit name.

Two limits, one in how I wrote the rules and one in the engine:

- **Hardcoded prefixes:** `ancestorPrefix` did not apply the `@Controller({ path, version })` prefix in this environment. I hardcoded each controller's prefix per file instead, along with `/api/v1`. The recipe will not follow a changed prefix or version. A new controller needs its own rule.
- **Empty-path decorators:** `@Get()` and `@Post()` with no argument needed separate rules, because `@$M($P)` doesn't match an empty argument list.
