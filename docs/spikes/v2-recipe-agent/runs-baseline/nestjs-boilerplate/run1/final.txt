I wrote the recipe to `.gantry/recipe.json`, and the dry-run says `ACCEPTED`. It lists 22 endpoints, 0 routes and 8 tables.

- **Stack:** NestJS with URI versioning. `main.ts` sets a global prefix (`API_PREFIX=api` in the env examples), and every controller uses version `1`. The code supports both TypeORM (relational) and Mongoose (document) persistence.
- **Endpoints (22):** Every one sits under `/api/v1/...`, except `GET /` from the home controller, which is excluded from the global prefix. Three of these are `/api/v1/files/...` routes, because the local uploader is the only files controller with a `@Get(':path')`.
- **Same-path files controllers:** The three files controllers (local, s3, s3-presigned) register `POST /files/upload` three times. The list shows it once, apparently because identical method and path entries merge.
- **Routes (0):** The repository is a backend only.
- **Tables (8):**
  - TypeORM entities: `file`, `role`, `session`, `status`, `user`.
  - Mongoose schemas, named by class because the schemas give no explicit name: `FileSchemaClass`, `SessionSchemaClass`, `UserSchemaClass`.

**Limitations:**
- **Hardcoded prefixes:** The `ancestorPrefix` option never applied the controller's `path` in this repo, even with the `export_statement` and `class_declaration` ancestors I tried. So I used one rule per controller directory, each with its prefix written as a literal (`/api/v1/auth`, `/api/v1/users`, and so on). A new controller needs its own rule.
- **Global prefix and version:** I wrote the global prefix and version as literals too, because the recipe can't read them from `setGlobalPrefix` or `enableVersioning`.
