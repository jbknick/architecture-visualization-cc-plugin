I wrote the recipe to `.gantry/recipe.json`. The dry-run says `ACCEPTED`, but the endpoint paths are incomplete because router mounts aren't being composed.

**Stack:** Go with chi v5 and bun. The database tables come from `CREATE TABLE` statements in Go migration files.

**What it lists:**
- **Routes:** 0. This is a pure API with no frontend pages.
- **Endpoints:** 16 listed, but only `/healthz`, `/*` and the `/login`, `/token`, `/refresh` and `/logout` routes are correct. The others lack their mount prefixes.
- **Tables:** 3 (`accounts`, `tokens`, `profiles`).

**What's wrong with the endpoints:**
- **Missing prefixes:** `/auth`, `/admin`, `/api/account`, `/api/profile` and `/admin/accounts` are not applied. For example, the account endpoints show as `GET /` and `PUT /token/{tokenID}`.
- **Missing endpoints:** the rule matched 19 registrations but only 16 are listed. The `/api/profile` endpoints and the admin `GET /` are the likely missing ones.
- **Cause:** I think `mount-graph` and `call-return` don't resolve mounts whose child is a method call on a struct field, such as `r.Mount("/account", a.Account.router())` or `r.Mount("/auth", authResource.Router())`. I made no second attempt to fix this.

I couldn't express that method-call mount case with the capabilities available.
