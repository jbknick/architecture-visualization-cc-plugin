The recipe is at `.gantry/recipe.json`, and the dry-run says `ACCEPTED` with all examples passing.

- **Stack:** Go with Gin (routing) and GORM (ORM).
- **Routes:** 0. The app is a backend API with no frontend pages.
- **Endpoints:** 20, with full `/api/...` paths. The articles, users, profiles and tags endpoints are included, along with `/api/ping` from `hello.go`. The routes registered with and without a trailing slash (`""` and `"/"`) each collapse to one endpoint.
- **Tables:** 6 — `ArticleModel`, `ArticleUserModel`, `FavoriteModel`, `TagModel`, `CommentModel`, `UserModel`/`FollowModel` (the last two from `users/models.go`). They come from structs that embed `gorm.Model`.

I could not express the prefixes for the `users` and `articles` route files through the mount graph. `hello.go` mounts them inline, as in `users.UsersRegister(v1.Group("/users"))`. The `mount-graph` and `param-flow` helpers did not carry those prefixes across packages, so the router-based rule dropped all 26 handlers in those files.

As a workaround, I hardcoded the prefix in one rule per register function, for example `UsersRegister` gets `/api/users`. If someone changes a prefix in `hello.go`, those rules need updating by hand.
