I wrote the recipe to `.gantry/recipe.json`, and the dry-run says ACCEPTED with all examples passing.

**Stack:** NestJS with TypeORM for the relational side and Mongoose for the document side. The app has no frontend.

**Counts:**
- **Routes:** 0.
- **Endpoints:** 22. `GET /` is the home controller, which the global prefix excludes. The other 21 are controller routes under `/api/v1/…` (auth, auth/apple, auth/facebook, auth/google, users, files).
- **Tables:** 8. These are five TypeORM entity names (`file`, `role`, `session`, `status`, `user`) and three Mongoose classes (`FileSchemaClass`, `SessionSchemaClass`, `UserSchemaClass`). The Mongoose classes duplicate the TypeORM entities, because the boilerplate supports both databases.

**What I could not express:**
- **Hard-coded prefix:** `/api` comes from the `API_PREFIX` environment variable, which defaults to `api`. I wrote it as the literal `/api/v1`, since every controller uses version `'1'`. If `API_PREFIX` is set differently or a controller changes version, the paths will be wrong.
- **Collapsed endpoints:** the local, S3 and S3-presigned files controllers share one path. I cannot tell which one is active, so `POST /api/v1/files/upload` appears once.
- **Plain schema classes:** I left out `RoleSchema` and `StatusSchema`. They are plain classes with no `@Schema` decorator, so I did not count them as tables.
