The recipe is at `.gantry/recipe.json`, and the dry-run says `ACCEPTED` with every example passing.

**Stack:** NestJS with TypeORM (relational) and Mongoose (document) persistence. This is a backend only, so there are no frontend routes.

**Counts**
- **Routes:** 0.
- **Endpoints:** 23. All are under `/api/v1/...`, from controllers with `path` and `version: '1'`. Examples are `/api/v1/auth/email/login`, `/api/v1/users/:id` and `/api/v1/files/upload`. `GET /` is the home controller, which the global prefix excludes.
- **Tables:** 10.
  - **Relational:** 5 TypeORM entities: `file`, `role`, `session`, `status`, `user`.
  - **Document:** 5 Mongoose schema classes, named by class: `FileSchemaClass`, `RoleSchema`, `SessionSchemaClass`, `StatusSchema`, `UserSchemaClass`. The code gives no explicit collection name for them.

**What I could not express**
- **Prefix and version are hardcoded:** `/api/v1` is written into the recipe because I couldn't read it from the code. The global prefix comes from the `API_PREFIX` setting (`api` in the env examples) and the version from `enableVersioning`.
- **Version is not read per controller:** every controller here uses version `1`. A controller with a different version would still get `/v1`.
- **Path-less handlers need their own rule:** `@Get()` and `@Post()` with no path run through separate rules. The first of these gets the controller prefix. The second is the home controller, which gets `/`.
