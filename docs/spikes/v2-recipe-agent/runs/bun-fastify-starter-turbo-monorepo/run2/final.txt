The recipe is at `.gantry/recipe.json`, and the dry-run says `ACCEPTED`.

**Stack:** Fastify 5 with Kysely on Postgres, in a Bun/Turbo monorepo. The backend is `apps/backend`.

**Listed:**
- **Routes:** 0. There is no frontend page code.
- **Endpoints:** 2.
  - `GET /`
  - `POST /users/email`
- **Tables:** 2, taken from the keys of the Kysely `Database` interface: `users` and `userProviders`. The `user_providers` spelling in the migration is not listed.

**Not expressed:** The recipe doesn't use the mount graph.
- Fastify composes paths through `fastify.register(plugin, { prefix })`, but the routes here sit in plain named functions registered as `register(fn)` or `register(fp(fn))`. The helpers couldn't tie those back to a router, because `fastify` is only a function parameter.
- The `/users` prefix is hard-coded in the `user-routes` rule, which only matches files named `apps/backend/src/api/users/*.route.ts`. A new route file in another folder won't be picked up until you add a rule for it.
- The `kysely-tables` rule only reads `apps/backend/src/db/types/index.ts`.

The first attempt at the user-routes rule failed its example. I rewrote the pattern as `fastify.$M($P, $S, $H)`, which matches three-argument calls only. A `fastify.post("/x", handler)` call with no options object would not match it.
