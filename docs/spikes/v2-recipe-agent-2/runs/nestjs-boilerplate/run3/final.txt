The recipe is at `.gantry/recipe.json` and the check passes. It covers tables and reads/writes only, not endpoints or routes.

**Stack:** NestJS with TypeORM on PostgreSQL. A Mongoose variant also exists in the repo.

**What the recipe produces:**
- **Tables:** 5, taken from the TypeORM entities' `@Entity({ name })`: `user`, `file`, `role`, `status` and `session`.
- **Reads and writes:** the 25 read matches and 53 write matches are call sites. They are on `this.xRepository` fields declared as `Repository<XEntity>`, and the engine reports one read or write per file and table. I expect roughly one read and one write for each of the 5 tables across the repository files. The seed services are probably included, because the rules match everything under `src/`. I haven't separated them out.
- **Endpoints:** 0.
- **Routes:** 0. The repo has no frontend pages.

**What I couldn't express:**
- **Endpoints:** about 30 NestJS handlers use `@Controller({path, version})` and `@Get`/`@Post`/`@Patch`/`@Delete` decorators, plus the global prefix set in `main.ts`. The endpoint emits need a router receiver, and I found no way to build full paths from controller decorators.
- **Mongoose tables:** the Mongoose schema classes (`UserSchemaClass`, `FileSchemaClass`, `SessionSchemaClass`) aren't included. I treated the TypeORM entities as the live schema. The Mongoose repositories use `@InjectModel` and `Model<...>`, so their reads and writes aren't covered either.
