The recipe is at `.gantry/recipe.json` and the check passes. It covers tables and database access only. It has no routes or endpoints, because the recipe format can't express NestJS's decorator-based routing.

**Stack:** NestJS with TypeORM (PostgreSQL) and Mongoose (MongoDB).

**What the recipe should produce:**
- **Routes:** 0. This is a backend-only API.
- **Endpoints:** 0. The controllers use `@Controller({path, version})` and `@Get`/`@Post` method decorators, with a global `api` prefix and URI versioning. The endpoint emit needs a router object, which these don't have.
- **Tables:** 8 from two rules, matching the 5 `@Entity` and 3 `@Schema` classes I counted. The TypeORM entities give `file`, `role`, `session`, `status` and `user`. The Mongoose schemas have no explicit name, so they are named by class (for example `UserSchemaClass`).
- **Reads and writes:** one rule each, matching `this.<field>.<method>(...)` calls on fields injected with `@InjectRepository` or `@InjectModel`. They should resolve to the user, file and session repositories in both database variants, plus the seed services (role, status and user), which I didn't exclude. Per-file read and write counts weren't checked. The check output only shows 208 raw pattern matches for each rule, which includes calls on non-repository fields that can't resolve to a table and so emit nothing.

I did not check that the injected-field lookup resolves to the right tables.
